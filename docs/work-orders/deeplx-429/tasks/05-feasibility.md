## Findings (2026-11-17)
No production edits or live translation calls made.

1. Confirmed transport approximation: `req/v3@v3.60.0/client.go:1212` delegates SetTLSFingerprintIOS to utls.HelloIOS_Auto; `utls@v1.8.2/u_common.go:648` aliases that to HelloIOS_14. DLX advertises iOS 26.0 and CFNetwork 3826.600.41 / Darwin 25.0.0. This is a real discrepancy but not proof that DeepL rejects it. A native Foundation URLSession same-payload comparison isolates the transport without inventing fingerprint values. Coordinator assigned that experiment elsewhere.
2. Confirmed fixed build provenance: `git show d44660c` identifies build 5443737 as DeepL iOS 26.42 metadata. Runtime diagnostic `$DLX_DIAGNOSTICS/dlx.log` resolved marketing version 26.58 and still got 429 (no Retry-After). A version/build mismatch is a hypothesis only: Easydict PR #1341 explicitly retains build 5443737 and reports successful real translation when merged. Do not guess build numbers. Source: https://github.com/tisfeng/Easydict/pull/1341 and https://github.com/OwO-Network/DLX/commit/d44660c9d0495e1448b6ccaeb8e11061430bcbe7 .
3. Authoritative current official Chrome extension downloaded in memory from Google's public update endpoint; manifest version 1.107.0, service_worker background.js, 58,041,468-byte CRX. URL: https://clients2.google.com/service/update2/crx?response=redirect&prodversion=140.0&acceptformat=crx2,crx3&x=id%3Dcofdbpoegempjloogbagkncekinflcnj%26uc . Source background.js confirms oneshot-free.www.deepl.com/v1 plus /translate; anonymous Authorization None; request fields text, target_lang, source_lang, usage_type, app_information. No endpoint/auth/body migration demonstrated. Metadata uses actual browser/platform (brex_*) and extension version, so not interchangeable blindly with iOS metadata.
4. Concrete current-client cookie difference: extension wrapper `ox` calls RP.fetch with omitCookies:true, passed as credentials:omit. DLX's shared cookie jar/warmup sends site cookies. That does not establish iOS behavior, but demonstrates anonymous oneshot does not require cookies for the extension. Proposed bounded second experiment if native TLS comparison is inconclusive: same Go client and unchanged body/headers, with empty jar and no warmup, one request only. If still 429, reject cookie hypothesis and stop this branch. Do not change TLS/profile at the same time.
5. Official extension reads X-Trace-ID for upstream errors; preserving that identifier would improve later upstream issue diagnosis, but is not a recovery fix.
6. Official https://www.deepl.com/translator HTML and initial script chunks fetched read-only with curl. Initial chunks show only bundled test-environment one-shot configuration, no actual current request serialization; no production endpoint inferred from test hosts. Python urllib got 403 while curl fetched HTML, which by itself proves neither translation IP blocking nor translation access.

Verification commands: local rg/git history/diff; public GitHub fetch; curl of translator/chunks and official extension update URL, ZipFile parsing in memory. No credentials, private browser state, or proxy changes. Native probe and optional cookie-only probe must report actual output before claiming recovered translation. No verified protocol correction available yet.
